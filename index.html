💡 Explicación Paso a Paso de fetch()

Aprende qué sucede internamente desde que llamas a la función hasta que muestras los datos en pantalla.

01

Llamada Inicial y Promesas

La función nativa fetch(url) inicia una petición de red HTTP asíncrona hacia la URL especificada. Retorna inmediatamente un objeto Promise (Promesa).

const respuesta = await fetch('https://pokeapi.co/api/v2/pokemon/ditto');
02

Objeto Response & Estado HTTP

La promesa del fetch no devuelve los datos directamente, sino un objeto Response con metadatos. Siempre debemos verificar si la respuesta fue exitosa usando response.ok.

if (!respuesta.ok) throw new Error('Error HTTP: ' + respuesta.status);
03

Lectura y Parseo a JSON

Para leer el cuerpo de la respuesta en formato JSON, llamamos a response.json(). Este método también es asíncrono y devuelve otra Promesa con el objeto transformado.

const pokemon = await respuesta.json();
04

Manejo de Errores con try...catch

Es fundamental envolver nuestro flujo en un bloque try...catch para capturar fallos de red (sin conexión, bloqueo CORS, URL inaccesible).

try { /* fetch */ } catch (error) { console.error(error); }

⚔️ Comparativa de Sintaxis: async/await vs .then()

Ambos enfoques funcionan exactamente igual por debajo, pero async/await ofrece una lectura secuencial y moderna.

✨ Opción 1: Modern Syntax (async / await) 
async function obtenerDitto() {
  try {
    // 1. Hacer la petición HTTP
    const res = await fetch('https://pokeapi.co/api/v2/pokemon/ditto');
    
    // 2. Validar que la respuesta sea OK (código 200-299)
    if (!res.ok) {
      throw new Error(`Error HTTP: ${res.status}`);
    }

    // 3. Parsear la respuesta a JSON
    const ditto = await res.json();
    
    // 4. Utilizar los datos recibidos
    console.log('Nombre:', ditto.name);
    console.log('Habilidades:', ditto.abilities);
  } catch (error) {
    // Captura errores de red o excepciones lanzadas
    console.error('Ocurrió un error:', error.message);
  }
}
📜 Opción 2: Promesas Tradicionales (.then / .catch) 
function obtenerDittoConPromesas() {
  // 1. Iniciar la petición fetch
  fetch('https://pokeapi.co/api/v2/pokemon/ditto')
    .then(res => {
      // 2. Validar respuesta HTTP
      if (!res.ok) {
        throw new Error(`Error HTTP: ${res.status}`);
      }
      // 3. Retornar la promesa de JSON
      return res.json();
    })
    .then(ditto => {
      // 4. Usar los datos de Ditto
      console.log('Nombre:', ditto.name);
      console.log('Habilidades:', ditto.abilities);
    })
    .catch(error => {
      // Manejar cualquier error de la cadena
      console.error('Ocurrió un error:', error.message);
    });
}

⚠️ Detalles Clave & Buenas Prácticas al usar fetch()

🛑

1. Fetch NO falla en 404 o 500

A diferencia de Axios o bibliotecas externas, fetch() solo rechaza la promesa ante fallos físicos de red (sin conexión). Ante un error 404 Not Found de la API, la promesa se resuelve con response.ok = false.

⏳

2. Dos Promesas en el proceso

Hay dos operaciones asíncronas involucradas: primero esperar la respuesta de la red (fetch), y luego descargar/parsear todo el body en JSON (response.json()).

📤

3. Enviar Datos (POST, PUT, DELETE)

Por defecto fetch hace peticiones GET. Para enviar datos debes pasar un objeto de opciones con method, headers y body (usualmente `JSON.stringify(datos)`).

🔒

4. Políticas CORS (Cross-Origin Resource Sharing)

PokéAPI es una API pública que permite llamadas cross-origin habilitando encabezados CORS (Access-Control-Allow-Origin: *), lo cual permite consumirla sin restricciones desde cualquier navegador.
